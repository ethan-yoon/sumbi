# Sumbi 설계 정리

작성일: 2026-11-27

## 1. 개요

- **1차 범위**: 수면에 올라온 다이버만 다룹니다. 수중 음향 통신은 제외합니다.
- **경쟁력의 핵심**: 수신기를 직접 만드는 것이 아니라, 수신된 신호를 다이빙 안전관리 정보로 바꾸는 소프트웨어입니다.
- **현장 후보**: 필리핀 보홀 알로나 비치. 발리카삭, 파밀라칸 방향을 커버합니다.

## 2. 시스템 구조

구조는 하이브리드입니다.

| 경로 | 송신 | 수신 | 용도 | 단계 |
| --- | --- | --- | --- | --- |
| AIS | 인증된 AIS MOB 비콘 (Nautilus, Ocean Signal MOB1 등) | dAISy HAT / RTL-SDR + AIS-catcher | 비상 SOS | 1차 |
| LoRa | 자체 제작 태그 (nRF52840 + SX1262 + GNSS) | SX1302 계열 컨센트레이터 | 인원 확인, 다이빙 기록 | 2차 |

두 경로 모두 같은 Raspberry Pi 게이트웨이로 모이고, 게이트웨이 앱이 MQTT로 관제 서버에 보냅니다.

## 3. 핵심 설계 결정

| 항목 | 결정 | 이유 |
| --- | --- | --- |
| 안테나 높이 | 긴 SMB(1.5~2m) 상단에 안테나 내장 | 손에 든 0.2m는 파도에 가립니다 |
| SMB 부풀리기 | 탱크에 남은 공기 사용 | 별도 가스가 필요 없습니다 |
| 헬륨 풍선 | 채택 안 함 | 고압 용기가 필요하고 바람에 눕습니다 |
| GPS 첫 위치 확보 | GNSS 백업 전원으로 hot start 유지 | 출수 직후 위치를 빨리 잡기 위해서 |
| 압력 센서 | 넣음 | 출수 자동 감지, 다이빙 기록 |
| SOS 버튼 | 3초 길게 누르기, 리드 스위치 또는 홀 센서 | 오경보 방지, 밀폐 설계 |
| 수신 확인 | 양방향 ACK (진동/LED) | 다이버의 심리적 안정 |
| SOS 이후 송신 | 짧은 주기에서 점점 길게 | 배터리 수 시간 이상 |
| 충전 | 무선 충전 또는 밀폐형 포고핀 | 부식 방지 |

해상 전파의 이론상 도달 거리: `d(km) ≈ 4.12 × (√h_tx + √h_rx)` (h는 m 단위 안테나 높이)

## 4. AIS 수신과 SOS 판정

AIS-catcher의 NMEA(`!AIVDM`) 출력을 게이트웨이 앱이 UDP로 받습니다.

SOS 판정 조건:

1. MMSI 앞자리가 `972`(MOB) 또는 `970`(SART)
2. Message 1의 항해 상태(navigational status)가 `14`
3. Message 14 문구
   - `MOB ACTIVE` / `SART ACTIVE` → 실제 조난
   - `MOB TEST` / `SART TEST` → 테스트

출항 전 체크인할 때 "기기 ID(MMSI) ↔ 다이버"를 연결해 다이버를 식별합니다.

## 5. 송신 테스트 방법

| 방법 | 검증 대상 |
| --- | --- |
| NMEA 재생 | 게이트웨이 앱, 서버, 알림 전체 |
| IQ 파일 생성 (GNU Radio) | AIS-catcher 디코딩 경로 |
| 케이블 직결 (감쇠기 60~100dB) | 실제 RF 송수신 |
| 인증 MOB 기기 TEST 모드 | 수면 높이 실제 수신 거리 |
| 자체 LoRa 송신기 | 야외 거리 테스트 (ISM 대역) |

- 직접 만든 송신기로 AIS 주파수에 전파를 내보내지 않습니다.
- 실제 `MOB ACTIVE`로 시험하지 않습니다. 현장 시험 전에는 필리핀 해안경비대(PCG)와 협의합니다.

## 6. 경쟁 제품

| 제품 | 방식 | 메모 |
| --- | --- | --- |
| ENOS (Seareq) | 다이버 송신기 + 보트 수신기 | 구조가 거의 같음. 나라별 주파수 규제로 보급이 더딤 |
| Nautilus Lifeline | 개인용 AIS/DSC 비콘, 약 200달러 | Sumbi는 이 기기의 신호를 받는 쪽 |
| Garmin Descent S1 | 수중 소나 네트워크, 부이 주변 약 100m | 해결하는 문제가 다름 |
